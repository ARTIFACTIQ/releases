Automating Ground Truth Quality Audits

Published February 5, 2026 | By Artifactiq ML Team

In our previous article, we described how we automated model evaluation using CI/CD pipelines. But there's a harder problem: what if the ground truth labels themselves are wrong?

Bad labels silently corrupt everything. Your precision and recall metrics become meaningless. Your model learns incorrect patterns. Your "improvements" might actually be regressions against the real world.

We built an automated system to detect these issues and made it publicly visible. Here's how.

The Problem: Silent Label Corruption

We discovered this issue while reviewing model comparison results. An image clearly showing a woman in a dress was labeled as "Boot". Our model correctly detected clothing items, but the evaluation marked them as false positives because they didn't match the erroneous "Boot" label.

The insidious part: These errors don't cause crashes or obvious failures. The pipeline runs successfully. Metrics are computed. Reports are generated. Everything looks fine—except the numbers are wrong.

Manual review doesn't scale. With 7,500+ validation images, each potentially containing multiple objects, human auditing would take weeks and still miss errors due to fatigue.

The Solution: Model-Assisted Auditing

We use our own trained model to audit the ground truth. The core insight: when a well-trained model confidently disagrees with a label, one of them is probably wrong.

The audit detects three types of issues:

Issue TypeSeverityDescription
Class Mismatch High Model confidently detects class X, GT says class Y (e.g., "Dress" detected, labeled "Boot")
Missing GT Medium Model detects an object with high confidence, but no GT label exists
Phantom GT Low GT label exists, but model detects nothing there (could be model limitation or bad label)

How It Works

1. Load trained model (E8.1) and validation images
↓
2. Run inference on each image
↓

↓
4. Flag mismatches where model confidence > threshold
↓
5. Generate JSON report with severity classification
↓
6. Publish to website for public review

Key Detection Logic

# Class mismatch detection
for detection in model_detections:
    best_gt = find_overlapping_gt(detection, ground_truth, iou_threshold=0.3)

    if best_gt and detection.class != best_gt.class:
        if not semantically_equivalent(detection.class, best_gt.class):
            flag_issue(
                type="class_mismatch",
                severity="high",
                description=f"Model: {detection.class} ({detection.conf}%), GT: {best_gt.class}"
            )

We allow semantic equivalence for related classes (e.g., "Clothing" and "Dress" don't flag a mismatch), but completely different classes (e.g., "Boot" vs "Dress") are flagged as high severity.

Why Make It Public?

We publish the full audit results at artifactiq.ai/gt-audit.html for several reasons:

  • Transparency: If our evaluation metrics are affected by bad labels, users should know
  • Community feedback: Domain experts might catch errors our model misses
  • Accountability: Public visibility creates pressure to actually fix issues
  • Trust: Acknowledging problems builds more credibility than hiding them
The feedback loop: Users can report corrections via GitHub issues. We review, fix the labels, regenerate the audit, and the public page updates automatically.

What We Can't Automate (Yet)

The ~20% we can't automate includes:

  • Subjective boundaries: Is a "blazer" a "jacket" or a "suit"? Reasonable people disagree.
  • Partial visibility: Should a half-visible shoe be labeled? Depends on annotation guidelines.
  • Model blind spots: If the model consistently misses a class, phantom GT issues for that class aren't useful signals.
  • Annotation style: Some datasets label every instance, others label one per category. Both are "correct."

These require human judgment and clear annotation guidelines—which we're developing based on patterns found in the audit.

Running the Audit

The audit script is available in our public repository:

python scripts/audit-ground-truth.py \
    --model models/e8_1_wavg_best.pt \
    --confidence 0.25 \
    --output gt-audit-results.json

Parameters:

  • --model: Path to the trained model weights
  • --confidence: Minimum confidence to flag issues (default: 0.5, we use 0.25)
  • --images: Validation images directory
  • --labels: Ground truth labels directory

Conclusion

Data quality is often overlooked in ML pipelines. We focus on model architectures, hyperparameters, and training techniques—but garbage in, garbage out.

By automating ~80% of quality detection and making results public, we've created a system that:

  • Catches label errors before they corrupt metrics
  • Scales with dataset size
  • Enables community participation
  • Builds trust through transparency

The code is open source. The results are public. The feedback loop is live.
